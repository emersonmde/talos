Problem statement
-----------------

The accepted cd fixed-directories candidate and the accepted literal-echo
control both fetched their selected kernels from TFTP on Pi 5 hardware after
build.rs routed their scenarios through TALOS_RPI5_EARLY_ENTRY_PROVENANCE_SCENARIO.
Both fresh serial captures then retained only NUL/space bytes and no
TALOS: asm_start, TALOS: asm_pre_rust_entry, Rust marker, prompt, classification,
or PASS.

That changes the blocker framing. The evidence is no longer cd-specific: the
same prompt-capable literal-echo control became non-responsive when the raw
pre-Rust assembly marker path was added. The invariant to preserve is that
prompt-capable RPi5 feature/control archives must not depend on raw UART writes
before BSS clear, stack setup, Rust entry, target init, and runtime-console
initialization unless that raw path is separately proven non-invasive.

Change
------

build.rs no longer defines TALOS_RPI5_EARLY_ENTRY_PROVENANCE_SCENARIO for:

- rpi5_local_literal_echo
- rpi5_local_cd_fixed_dirs

The boot.S implementation remains available for RPi5 SMP scenarios that already
owned raw early UART marker use, but the prompt-capable local command-loop
control/candidate archives no longer carry the unproven earliest assembly marker
path.
